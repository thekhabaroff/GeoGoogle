# GeoGoogle

Мониторинг региона YouTube и рекламных блоков на Linux-сервере. Установщик
`geogoogle.sh` собирает Docker-образ и запускает контейнер **`geogoogle`**.
При смене региона бот отправляет уведомление в Telegram и указывает, удалось ли
обнаружить рекламные блоки.

## Как работает мониторинг

1. Определяет регион по полю `GL` на главной странице YouTube.
2. Для любого определённого региона проверяет до трёх видео, включая `MD`,
   `RU` и остальные страны.
3. Реклама подтверждается, если доступный плеер
   (`playabilityStatus.status == "OK"`) содержит непустой массив
   `adPlacements`.
4. При смене региона отправляет уведомление с именем ноды, внешним IPv4,
   регионом и результатом проверки `adPlacements`.

Последний обнаруженный регион сохраняется в `/opt/geogoogle/state/last-region`
и переживает перезапуск или обновление контейнера. При смене региона уведомление
отправляется всегда: и когда реклама обнаружена, и когда `adPlacements` не найдены,
и когда плеер недоступен. В сообщении указывается результат проверки.
Повторные проверки того же региона уведомлений не вызывают, даже если результат
проверки `adPlacements` изменился. Регион сохраняется после проверки независимо
от наличия рекламных блоков.

Мониторинг продолжает работать при любом регионе, без ограничения по сроку.
Неизвестный регион и ошибки получения региона попадают в логи и не вызывают
уведомление, поскольку сравнить смену региона нельзя. Ошибки проверки рекламы
указываются в уведомлении при смене региона.

Регион и статус `adPlacements` указываются в уведомлениях. Уведомление означает
смену региона; наличие `adPlacements` не гарантирует показ рекламы каждому
зрителю.

## Расписание

Проверки начинаются в `00` минут каждого часа по UTC: `00:00`, `01:00`, …,
`23:00`. Для Москвы (UTC+3) это также начало каждого местного часа.

Первая проверка начинается сразу после запуска контейнера во время установки.
Например, если контейнер запущен в `12:34`, первая проверка начнётся сразу, а
следующая — в `13:00`. Если часовая проверка закончится в `13:02`, следующая
начнётся в `14:00`.

Планировщик допускает пробуждение в течение первой минуты часа. Если после
паузы контейнер возобновится позднее этой минуты, пропущенная проверка не
выполняется; планировщик ждёт следующего часа.

Сообщение отправляется после получения результатов DNS и HTTP-запросов.
Отправка и доставка Telegram не гарантируются ровно в нулевую секунду.
После ошибки отправки уведомление для этого региона не повторяется; новое
уведомление возможно при обнаружении другого региона с рекламными блоками.
Время в логах указано в UTC.

## Требования

- Linux-сервер, Bash и стандартные Unix-утилиты, включая `stty`.
- `curl` на сервере для установки одной командой.
- Права `root` и интерактивный терминал для установки и обновления.
- Установленный и запущенный [Docker Engine](https://docs.docker.com/engine/install/).
- Исходящий доступ по IPv4 к YouTube и Telegram API, а также доступ к Docker
  Registry и репозиториям Alpine для сборки образа.
- DNS-запросы к `8.8.8.8` либо доступ к резервным DNS-over-HTTPS сервисам Google
  и Cloudflare (`1.1.1.1`).

Docker, Python, `curl`, `jq` и DNS-утилиты на хост автоматически не устанавливаются.
Python, `curl`, `jq` и DNS-утилиты включаются в образ. Docker должен быть готов
до запуска установщика.

## Установка

На сервере с установленным и запущенным Docker выполните в интерактивном
терминале одну команду:

```bash
curl -fsSL https://raw.githubusercontent.com/thekhabaroff/GeoGoogle/master/geogoogle.sh | sudo bash
```

Команда скачает установщик из ветки `master` и запустит его с правами `root`.

Если репозиторий уже скачан, откройте его каталог и запустите установщик:

```bash
sudo bash geogoogle.sh
```

Введите по порядку:

1. **Токен бота** — получите у [@BotFather](https://t.me/BotFather). Ввод скрыт.
2. **Chat ID** — идентификатор чата, куда бот может отправлять сообщения.
3. **Имя ноды** — подпись сервера в уведомлениях.

Все три значения обязательны. В личном чате сначала начните диалог с ботом;
для группы добавьте бота и предоставьте ему право отправлять сообщения.

Установщик создаст файлы в `/opt/geogoogle`, соберёт образ `geogoogle:local`,
запустит контейнер `geogoogle` и будет ждать состояния `healthy` до 90 секунд.
Это проверка работы процесса и планировщика; токен и возможность отправки
сообщения будут проверены только при подходящем результате мониторинга.
Тестовое сообщение при установке не отправляется.

Контейнер использует сеть хоста (`--network host`) и его исходящий IPv4-маршрут.
VPN, прокси и правила маршрутизации сервера могут влиять на результат.

## Управление

| Действие | Команда |
| --- | --- |
| Состояние контейнера | `sudo docker ps -a --filter name=^/geogoogle$` |
| Последние логи | `sudo docker logs --tail 100 geogoogle` |
| Смотреть логи | `sudo docker logs --tail 100 -f geogoogle` |
| Статус healthcheck | `sudo docker inspect --format '{{.State.Health.Status}}' geogoogle` |
| История healthcheck | `sudo docker inspect --format '{{json .State.Health}}' geogoogle` |
| Остановить | `sudo docker stop geogoogle` |
| Запустить | `sudo docker start geogoogle` |
| Перезапустить | `sudo docker restart geogoogle` |

Используется политика `unless-stopped`: контейнер запускается после перезапуска
Docker, если он не был остановлен вручную. Docker Engine также должен
запускаться при загрузке сервера.

## Healthcheck

Healthcheck выполняется каждые **30 секунд**, с тайм-аутом **5 секунд**, начальным
периодом **10 секунд** и порогом **3 неудачных проверок**. Он проверяет:

- существование процесса мониторинга;
- наличие корректного heartbeat, обновлённого не более 300 секунд назад.

Планировщик обновляет heartbeat каждые 30 секунд во время ожидания, а также до
и после работы по расписанию. Возраст heartbeat рассчитывается по
`/proc/uptime` и не зависит от перевода системных часов.

Healthcheck не обращается к YouTube и Telegram и не отправляет сообщения.
Статус `healthy` означает работоспособность локального процесса, а не успешную
проверку внешних сервисов. Сетевые ошибки смотрите в логах.

Статус `unhealthy` сам по себе не вызывает перезапуск Docker-контейнера.
После устранения причины выполните `sudo docker restart geogoogle`.
Политика перезапуска описана в [документации Docker](https://docs.docker.com/engine/containers/start-containers-automatically/).

## Ошибки Telegram

При отказе Telegram в логах указываются HTTP-код и описание ошибки из ответа
API. Если Telegram сообщает о миграции группы, отдельно выводится новый
Chat ID; для его изменения повторите установку с актуальными настройками.

Проверить доступ бота к настроенному чату без отправки сообщения можно так:

```bash
sudo docker exec geogoogle bash -c 'source /run/geogoogle-config.sh; curl -4 -sS --connect-timeout 5 --max-time 20 --get --data-urlencode "chat_id=$CHAT_ID" "https://api.telegram.org/bot$BOT_TOKEN/getChat" | jq "{ok, error_code, description, chat: (if .ok then {id: .result.id, type: .result.type} else null end)}"'
```

Команда использует сохранённые настройки и выводит результат `getChat` без
токена. `ok: true` подтверждает доступ к информации о чате, но не гарантирует
право отправлять в него сообщения. При `ok: false` смотрите `description`:
проверьте Chat ID, присутствие бота в чате и его права.

`Bad Request: chat not found` означает, что указанный чат недоступен этому
боту. Сверьте Chat ID и убедитесь, что добавлен именно бот, чей токен указан
при установке. В группе разрешите ему отправлять сообщения; в канале
назначьте администратором с правом публикации. После исправления доступа
повторите `getChat`. Если Chat ID и токен не менялись, переустановка не нужна.

## Обновление и смена настроек

Обновите `geogoogle.sh` из выбранной версии репозитория и снова выполните:

```bash
sudo bash geogoogle.sh
```

Введите актуальные токен, chat ID и имя ноды. Повторная установка пересобирает
образ и заменяет контейнер. При ошибке сборки прежний контейнер продолжает
работать. При ошибке запуска или healthcheck установщик пытается восстановить
прежний контейнер и конфигурацию. Восстановленный контейнер запускается, если
до обновления он работал.

Если имя `geogoogle` занято контейнером, созданным другим способом, установщик
завершится с сообщением. Переименуйте такой контейнер перед установкой.

После успешного запуска установщик удаляет из crontab текущего пользователя
(`root`) записи с `/opt/yt-geo-monitoring.sh` и связанные файлы старой проверялки.
Другие задания cron сохраняются. Уже запущенный старый процесс может закончить
свою текущую проверку.

## Файлы и настройки

| Путь на сервере | Назначение |
| --- | --- |
| `/opt/geogoogle/config.sh` | Токен, chat ID и имя ноды |
| `/opt/geogoogle/state/last-region` | Последний обнаруженный регион для дедупликации уведомлений |
| `/opt/geogoogle/Dockerfile` | Описание Docker-образа |
| `/opt/geogoogle/monitor.sh` | Планировщик и мониторинг |
| `/opt/geogoogle/parse-player.py` | Разбор JSON плеера YouTube |
| `/opt/geogoogle/healthcheck.sh` | Проверка состояния процесса |
| `/opt/geogoogle/.dockerignore` | Исключение конфигурации из контекста сборки |

Каталог установки имеет права `0700`, конфигурация — `0600`. Конфигурация
монтируется в контейнер только для чтения; токен не включается в Docker-образ.
Файл `config.sh` является Bash-конфигурацией и загружается через `source`.
Для изменения настроек используйте повторный запуск установщика.

Корневая файловая система контейнера доступна только для чтения; временные
данные хранятся в `tmpfs`. Логи ротируются: до трёх файлов по 10 МБ.

## Удаление

Удалите контейнер:

```bash
sudo docker rm -f geogoogle
```

Если настройки и образ больше не нужны, удалите их отдельно:

```bash
sudo docker image rm geogoogle:local
sudo rm -rf /opt/geogoogle
```

## Разработка и GitHub Actions

В репозиторий входят `geogoogle.sh`, документация, лицензия, `scripts`, `tests`
и настройки GitHub Actions. `.gitignore` разрешает только файлы проекта:
локальные сетевые конфигурации из этой рабочей папки не включаются.

Локальная проверка требует Python 3 и ShellCheck:

```bash
python3 -B scripts/check.py
```

CI проверяет установщик и извлечённые из него файлы, выполняет офлайн-тесты,
собирает Docker-образ и проверяет переходы `healthy`/`unhealthy` с отключённой
сетью контейнера. Для CI не нужны настоящие токены Telegram.

При установленном Docker ту же сборку и проверку контейнера можно выполнить
локально:

```bash
python3 -B scripts/docker_smoke.py
```

Результат YouTube зависит от его HTML/JSON, антибот-защиты и текущих ответов
сервиса. При изменении формата ответа может потребоваться обновление парсера.
